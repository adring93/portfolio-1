How I work

My practical process

01

Understand the goal

I start by reading the brief carefully and turning the requirements into a clear checklist. This helps me avoid building the wrong thing.

02

Build in small steps

I work best when I split a project into smaller parts, get one feature working, test it, then move to the next part.

03

Improve from feedback

I try to use teacher feedback directly. For Portfolio 2, I fixed bugs, improved interaction feedback and refined visual presentation.

04

Test the real experience

I check the deployed site, not only the local code. I test navigation, refresh, links, forms and whether the user actually understands what happened.
